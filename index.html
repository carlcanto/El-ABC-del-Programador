07 Control de Versiones

Git: La Máquina del Tiempo

Cada commit es una fotografía de tu código. Puedes viajar al pasado.

¿Qué es Git?
Git es un sistema de control de versiones distribuido que permite a cada desarrollador mantener una copia completa del historial del proyecto en su máquina local, facilitando el trabajo autónomo y sin dependencia de conexión constante.
Commit
Una instantánea de un estado funcional del código. Cada commit debe ir acompañado de un mensaje claro que explique el 'por qué' de los cambios, no solo el 'qué'.

.gitignore

Un archivo donde le dices a Git qué NO debe guardar:
  • ✓ Carpetas temporales
  • ✓ Archivos enormes
  • ✓ Contraseñas
  • ✓ Dependencias que se pueden reinstalar
Branch (Rama)
Permite crear caminos de desarrollo paralelos. Las ramas son ideales para trabajar en nuevas funcionalidades o corregir errores de forma aislada, sin afectar la versión principal del proyecto.

Conceptos Clave

  • ● Git es la "máquina del tiempo" para tu código
  • ● Cada commit es un punto en el tiempo que puedes visitar
  • ● Las ramas son bifurcaciones que permiten experimentar sin riesgo

12 El Dolor

Funciona en mi Máquina

El problema de los entornos no reproducibles.

"¡Funciona en mi máquina!"

Cuando el código que opera perfectamente en el entorno de un programador falla al trasladarse a otro entorno.

Raíz del Problema
Las versiones específicas de:
  • • Lenguajes de programación (Python, Java, etc.)
  • • Bases de datos y librerías
  • • Sistema operativo subyacente

Se pierde tiempo valioso configurando y depurando entornos, en lugar de desarrollar nuevas funcionalidades.

Entornos Inconsistentes
✓ Desarrollo Python 3.9 · Ubuntu 20.04
⚠ Pruebas Python 3.8 · Ubuntu 18.04
✗ Producción Python 3.7 · Ubuntu 16.04
La Solución: Docker — Docker emerge como una solución fundamental para mitigar este caos y garantizar la consistencia en todos los ciclos de vida del desarrollo.
Contenerización = Consistencia + Portabilidad

14 Contenedores

Docker

Así como un contenedor marítimo estandariza el transporte de carga, Docker estandariza el despliegue de aplicaciones.

Contenedor marítimo → funciona en cualquier barco
Contenedor Docker → funciona en cualquier servidor
Concepto de Imagen

Es la plantilla estática e inmutable de un contenedor. Piensa en ella como la "receta" que define todo lo necesario para que tu aplicación funcione.

Concepto de Contenedor

Es una instancia ejecutable de una Imagen. Es el proceso aislado que ejecuta tu aplicación. Los contenedores son ligeros, se inician rápidamente y comparten el kernel del sistema.

Elimina el problema del "funciona en mi máquina" Proporciona entornos consistentes para desarrollo y producción Facilita la portabilidad de aplicaciones entre sistemas

16 Construcción

Dockerfile

La receta para construir una imagen Docker.

1FROM python:3.9-slim
2WORKDIR /app
3COPY app.py .
4CMD ["python", "app.py"]
1 FROM — Define la imagen base (un ambiente Python ligero)
2 WORKDIR — Establece el directorio de trabajo dentro del contenedor
3 COPY — Copia el archivo de tu aplicación al directorio de trabajo
4 CMD — Define el comando que se ejecutará al iniciar el contenedor
Estas pocas líneas garantizan que cualquier persona en el equipo, o cualquier servidor, podrá ejecutar la aplicación sin preocuparse por instalar Python 3.9 o configurar el entorno.
17 En Vivo

Demo Docker

1 Crear código + Dockerfile
2 docker build
3 docker run
Docker es el vehículo de entrega de tu software. Nos da entornos consistentes para desarrollo, pruebas y producción.
$echo 'print("Hola, soy un contenedor Docker!")' > app.py
$cat > Dockerfile << EOF
FROM python:3.9-slim
WORKDIR /app
COPY app.py .
CMD ["python", "app.py"]
$EOF
$docker build -t mi-saludo . → Successfully built mi-saludo
$docker run mi-saludo → Hola, soy un contenedor Docker!

Taller Práctico

git initInicializa un repositorio Git vacío

git status -sVersión corta del estado
git add .Agrega todos los cambios al área de staging

git log --onelineHistorial resumido de commits
